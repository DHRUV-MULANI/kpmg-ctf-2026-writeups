## 4. Layer 1 & 2 — PrivateBin analysis (full detail)

### 4.1 What the link contains

```
https://privatebin.net/?affd7f2ac40d9ab0#8DPEkPZMJFcPWGWXGLbF4Nd3afesNEWs9agcT4VSsoA9
                            └── paste ID ──┘ └──────────── decryption key ────────────┘
```

PrivateBin is a **zero-knowledge** pastebin: the server stores only ciphertext, and the AES key lives in the URL fragment (`#...`), which is never sent to the server.

### 4.2 Fetching the ciphertext

The server returns JSON when asked with `X-Requested-With: JSONHttpRequest`:

```bash
curl -s -H "X-Requested-With: JSONHttpRequest" "https://privatebin.net/?affd7f2ac40d9ab0"
```

Response (`evidence/privatebin_response.json`):

### 4.3 The cryptographic specification (`adata[0]`)

| Field | Value | Meaning |
|---|---|---|
| `adata[0][0]` | `ReCLDZdLm/U8wIfY+KaGKw==` | 16-byte AES-GCM IV |
| `adata[0][1]` | `+4NrCDF6600=` | 8-byte PBKDF2 salt |
| `adata[0][2]` | `100000` | PBKDF2 iterations (SHA-256) |
| `adata[0][3]` | `256` | AES key size (bits) |
| `adata[0][4]` | `128` | GCM tag size (bits) |
| `adata[0][5]` | `"aes"` | Cipher |
| `adata[0][6]` | `"gcm"` | Mode |
| `adata[0][7]` | `"zlib"` | Compression of plaintext |
| `adata[1]` | `"plaintext"` | Paste format |
| `adata[2]`, `adata[3]` | `0`, `0` | Open discussion / burn-after-reading |

### 4.4 Reverse-engineering PrivateBin 2.0.6

The instance serves `js/privatebin.js?2.0.6`. The relevant logic (`CryptTool`):

```js
// key from URL fragment (version 2 => base58, version 1 => base64)
symmetricKey = CryptTool.base58decode(newKey).padStart(32, '\u0000');

async function deriveKey(key, password, spec) {
    let keyArray = stringToArraybuffer(key);
    if (password.length > 0) {                       // <-- a password is APPENDED to the key
        let passwordArray = stringToArraybuffer(password);
        let newKeyArray = new Uint8Array(keyArray.length + passwordArray.length);
        newKeyArray.set(keyArray, 0);
        newKeyArray.set(passwordArray, keyArray.length);
        keyArray = newKeyArray;
    }
    const importedKey = await crypto.subtle.importKey('raw', keyArray, {name:'PBKDF2'}, false, ['deriveKey']);
    return crypto.subtle.deriveKey(
        { name:'PBKDF2', salt: stringToArraybuffer(spec[1]), iterations: spec[2], hash:{name:'SHA-256'} },
        importedKey,
        { name: 'AES-' + spec[6].toUpperCase(), length: spec[3] },
        false, ['encrypt','decrypt']
    );
}

// decrypt
spec[0] = atob(spec[0]); spec[1] = atob(spec[1]);          // IV, salt -> raw bytes
plaintext = await crypto.subtle.decrypt(
    { name:'AES-GCM', iv: spec[0], additionalData: stringToArraybuffer(JSON.stringify(adata)), tagLength: spec[4] },
    await deriveKey(key, password, spec),
    stringToArraybuffer(atob(cipherMessage))
);
// then zlib-inflate
```

Key facts extracted:

* **v2 key encoding = Bitcoin base58** (alphabet `123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz`), decoded and left-padded with `\u0000` to 32 bytes.
* The URL fragment is **44 chars → 32 bytes**, no leading zero bytes needed.
* **AAD (additional authenticated data) = `JSON.stringify(adata)`** — i.e. the *whole* `adata` array, reserialised compactly with **unescaped `/`** (PHP's `json_encode` escapes `/` on the wire, but JS `JSON.stringify` does not, and the AAD is produced client-side).
* **When a password is set, the password bytes are appended to the 32-byte key before PBKDF2.**
